# bitis golden vectors

Language-neutral test vectors for the bitis wire format (docs/WIRE_FORMAT.md). Every
runtime (Rust, C++, Python via Rust, Dart) tests against the SAME committed files, so a
difference between a runtime and the spec, or between two runtimes, is detected.

The Rust runtime is the reference: valid vectors are the bytes it produces. Invalid and
non-canonical inputs are built bit by bit by the generator with an independent writer (a
direct transcription of the spec) together with the error the SPEC requires; the generator
refuses to write the manifest if the Rust runtime disagrees.

## Layout

```
golden/
  schema/golden.bitis       one schema covering every type and edge
  gen/rust/golden.rs        generated from the schema (committed, see "Regeneration")
  gen/cpp/golden.h          generated from the schema (includes "bitis_lib.h" from cpp_lib/)
  gen/dart/golden.dart      generated from the schema (imports package:bitis)
  vectors/manifest.txt      the vectors (GENERATED, do not edit)
  vectors/crc32.txt         CRC-32 helper vectors (GENERATED by vectors/crc32_gen.py, see "CRC-32 vectors")
  vectors/crc8_16.txt       CRC-8/16 + transmission CRC vectors (GENERATED by vectors/crc8_16_gen.py, see "CRC-8/16 vectors")
  gen_rust/                 generator of manifest.txt (cargo project, path dependency on bitis)
  cpp/golden_test.cpp       C++ test (gtest target bitis_golden, built by cpp_lib/tests)
  dart/                     Dart test package (path dependency on dart/bitis)
    tool/embed_manifest.dart  writes test/manifest.g.dart from vectors/manifest.txt
    test/manifest.g.dart      the manifest as a Dart string (GENERATED, for the web)
    test/manifest.dart        parser, dispatch over the 16 message types
    test/golden_test.dart     the per-record checks + JSON round trip
    test/spot_checks_test.dart decoded values and encoder spot checks
  python/                   Python tests (pytest) of the module generated from the schema
    build.sh                  builds the module `golden` into a venv (not committed, in target/golden/python)
    test_golden.py            the per-record checks, spot checks, exceptions, .pyi stub (mypy)
    test_crc32.py             CRC-32 helper
    test_crc8_16.py           CRC-8/AUTOSAR, CRC-16/IBM-3740, transmission CRC
  run_all.sh                runs all golden tests
tests/golden.rs             Rust test (cargo test --test golden)
```

## Schema

`schema/golden.bitis` contains (message types used in the manifest in bold):

| Message | Covers |
|---|---|
| **Ints** | bool; uint_1/7/32/33/63/64; int_1/7/16/32/33/64 |
| **DynInts** | uint_8d3, uint_32d4, uint_64d64, uint_64d7, int_16d5, int_64d8 |
| **Floats** | float, double |
| **FixedPoints** | fp_2[0,1], fp_10[-2,3], fp_34[-90,90] (GNSS lat), fp_35[-180,180] (GNSS lng), fp_53[-1000000,1000000] |
| **Texts** | astr_d4, binary_d4 |
| **Leaf** / **Mid** / **Nested** | three nesting levels, optional message |
| **Containers** | optional scalar/message/string/enum; repeated_fixed of scalars and messages; repeated_dyn of scalars, bools, strings and messages |
| **Enums** | enum with 6 variants and dyn bits 2 (`Color`), enum with dyn bits 1 (`Level`), repeated enum |
| **IntList** | repeated_dyn of int_7 (the "repeated" oneof variant) |
| **Choice** | oneof(2) with bool / double / astr / message / repeated (IntList) / empty message / int_32d7 variants, followed by a bool |
| **Empty** | empty message (0 bits) |
| **Everything** | all of the above in one message (except Bounds, see below) |
| **BoundsItem** / **Bounds** | maximum lengths `[M]` (spec 2.16): `astr_d4[8]`, `binary_d3[4]`, `repeated_dyn_2[3] astr_d2[2]` (bounded list of bounded strings), `optional astr_d4[5]`, `repeated_dyn_3[2] BoundsItem` with an `optional astr_d2[3]` inside; kept out of Everything so that the existing vectors did not change |

## Manifest format

`vectors/manifest.txt` is line based so that it can be parsed without a JSON library.
Fields are separated by exactly one space; lines starting with `#` and empty lines are
comments. Hex strings are lower case without separators; `-` stands for empty input.

```
valid    <case> <MsgType> <total_bits> <hex>
noncanon <case> <MsgType> <total_bits> <input_hex> <canonical_hex>
invalid  <case> <MsgType> <error> <default|exact> <hex>
min_bits <MsgType> <min_bits>
max_bits <MsgType> <max_bits|unbounded>
```

`<case>` matches `[a-z0-9_]+` and is unique; `<MsgType>` is the message name from the
schema; `<error>` is one of `UnexpectedEnd`, `InvalidValue`, `InvalidDiscriminant`,
`TrailingData` (spec section 3). The header comment contains the schema hash of the schema
the vectors were generated for.

What every runtime has to check:

| Record | Check |
|---|---|
| `valid` | decode with the default and the exact decoder succeeds and consumes `total_bits`; re-encoding the decoded value gives exactly `hex`; with two extra bytes appended the default decoder still succeeds (same `total_bits`, same re-encoding) and the exact decoder fails with `TrailingData` |
| `noncanon` | decoding `input_hex` (default and exact) succeeds and consumes `total_bits`; re-encoding gives `canonical_hex` |
| `invalid` | decoding `hex` with the given decoder (`default`: `try_deserialize`, `exact`: `try_deserialize_exact`) fails with `error` |
| `min_bits` | `min_bits()` of the message type (spec section 4) |
| `max_bits` | `max_bits()` of the message type (spec section 4), `unbounded` if there is no upper bound (Rust `None`, C++ `BITIS_UNBOUNDED`, Dart `null`); every `valid` encoding is at most `max_bits` bits. |

Notes on the vectors:

- Floats only use the canonical quiet NaN (`0x7fc00000` / `0x7ff8000000000000`), see spec 2.6.
- Fixed point: the default value of a fixed point attribute is **Overflow** (raw `2^N-1`) in
  Rust, C++ and Dart (`fixedpoints_default`, `everything_default`). `fixedpoints_ties` contains
  values for which the encoder computes an exact tie `t = k + 0.5` with even `k`
  (round half away from zero gives `k + 1`, round half to even would give `k`);
  `fixedpoints_gnss` contains `fp2 = 0.49999999999999994`, which becomes the tie `1.5` in
  f64 arithmetic. These two are also checked as encoder spot checks (value -> bytes).
- Negative zero (sign bit 1, magnitude 0) is decode-only (`noncanon_*_negzero`).
- Decoders accept non-minimal dynamic integers (continuation bit 1 followed by zero chunks)
  for values, counts, enum and oneof indices, and ignore padding bits (`noncanon_*`).
- Maximum lengths (spec 2.16): `bounds_max` has every bounded field at exactly `M` and
  reaches `max_bits` exactly; a count of `M + 1` is `InvalidValue` (`bounds_*_count_*`,
  also for an element of a bounded list and inside an optional or a list element), and
  so is a count `> M` whose data is missing (`bounds_*_short`): the bound is checked
  directly after the count, before the count check of spec section 3. A count of `M`
  with missing data is `UnexpectedEnd` (`bounds_name_count_8_short`). The encoders reject
  values longer than `M` (Rust `try_serialize`, Dart `toBytes`: `ValueOutOfRange`; the
  C++ containers cannot hold them) and the legacy Rust `serialize` writes the first `M`
  elements (spot checks).
- First error wins: an error is reported where it is detected, before the (missing) rest
  of the input (`enum_invalid_then_end`, `int16_invalid_then_end`); the count check of
  astr/binary/repeated_dyn comes before reading the elements (`astr_non_ascii_truncated`
  is `UnexpectedEnd`).

Cases (55 valid, 10 non-canonical, 85 invalid, 16 min_bits, 16 max_bits): defaults; min/max and 2^k
values of every integer width; i64/i32/i16 range limits (the base type minimum is invalid);
dyn int chunk boundaries (incl. uint_64d64 single chunk and the final 1 bit chunk of
uint_64d7); ±0.0, ±inf, NaN, subnormals, extremes; fixed point min/max/underflow/overflow/
NaN/±inf/ties/GNSS values; empty, ASCII edge (NUL, DEL) and long (multi chunk count)
strings and binaries; empty and full containers; every enum and oneof variant; deep
nesting; everything set; truncations of many vectors (incl. empty input); huge counts
(must fail without allocating); unknown enum/oneof indices (incl. 2^32-1, inside arrays,
optionals and nested messages); out-of-range magnitudes of int_16/int_32/int_64,
int_16d5/int_64d8/int_32d7; non-ASCII bytes (top level, nested, in arrays); trailing data
in exact mode; maximum lengths (at `M`, `M + 1`, `M + 1` with missing data, truncations).

## Running

All at once (Rust, C++ plain and with ASan/UBSan, Python, Dart on the VM and in Chrome with
dart2js and dart2wasm):

```
golden/run_all.sh            # --no-asan to skip the sanitizer build
# offline: CARGO_FLAGS=--offline DART_PUB_FLAGS=--offline \
#          FETCHCONTENT_SOURCE_DIR_GOOGLETEST=<googletest checkout> golden/run_all.sh
```

The Python step uses the venv `$BITIS_PYTHON_VENV`, else the active venv (`$VIRTUAL_ENV`) if
it contains maturin, and is reported as SKIP otherwise. Setting up such a venv once:

```
python3 -m venv ~/.venvs/bitis && ~/.venvs/bitis/bin/pip install maturin pytest mypy
BITIS_PYTHON_VENV=~/.venvs/bitis golden/run_all.sh
```

The Dart steps use `$DART`, else `dart` on PATH, else `/home/dheide/sdk/flutter/bin/dart`
if it exists, and are reported as SKIP if no dart is found; the two Chrome steps are
skipped if no Chrome is found (`CHROME_EXECUTABLE`, or `google-chrome` / `chromium` on
PATH).

Individually:

- **Manifest up to date**: `cargo run --manifest-path golden/gen_rust/Cargo.toml -- --check`
- **Rust**: `cargo test --test golden` (also checks that golden/gen/ is the current
  compiler output and that the manifest belongs to the schema)
- **C++**: target `bitis_golden` of cpp_lib/tests (`run_all.sh` builds all targets of
  cpp_lib/tests and runs them with ctest, so the unit tests run as well):
  ```
  cmake -S cpp_lib -B build && cmake --build build --target bitis_golden && build/tests/bitis_golden
  cmake -S cpp_lib -B build-asan -DBITIS_SANITIZE=ON && cmake --build build-asan --target bitis_golden && build-asan/tests/bitis_golden
  ```
  The manifest path is compiled in (`BITIS_GOLDEN_MANIFEST`). With ASan in some
  environments `ASAN_OPTIONS=verify_asan_link_order=0` is needed, also during the build
  (gtest_discover_tests runs the binary).
- **Python**: directory `golden/python/`:
  ```
  BITIS_PYTHON_VENV=<venv> golden/python/build.sh          # --no-snapshots: only the module
  BITIS_PY_MODULE=golden <venv>/bin/python -m pytest golden/python
  ```
  `build.sh` builds the compiler, writes the maturin project `target/golden/python/golden`
  (Cargo.toml with a path dependency on this repository, pyproject.toml, package dir
  `golden/`), runs `bitis compile -l python` (generates the code, sets version / pyo3 /
  strum_macros in Cargo.toml, runs `maturin develop`, which installs the module into the
  venv) and then `cargo check`s the Python bindings of every codegen snapshot
  (`tests/snapshots/<name>/py_*.rs`) as crates in `target/golden/python/snapshot_<name>`,
  so that the committed snapshots are known to compile with pyo3. `test_golden.py`
  (module from `BITIS_PY_MODULE`, default `golden`) runs the checks of the table above
  with `try_deserialize` (default decoder, returns `(msg, total_bits, total_bytes)`),
  `try_deserialize_exact` and the legacy `deserialize` (`invalid` records: `DecodeError`
  with `kind` = the manifest error and a message starting with `"<kind>: "`), re-encodes
  with `try_serialize` and the legacy `serialize`, checks `min_bits()` / `max_bits()`
  (`unbounded` = `None`); unknown record types are ignored. Spot checks: decoded integers,
  floats, fixed point values (Overflow reads back as `max + 1`, Underflow as `min - 1`),
  strings, binaries, containers, enums, oneofs, nesting, bounds; encoder: `fixedpoints_ties`,
  `fixedpoints_gnss`, `fixedpoints_underflow`, `ints_min`, `texts_values`, out-of-range
  values and non-ASCII strings (`EncodeError` kind `ValueOutOfRange` from `try_serialize`,
  no exception from `serialize`), too long bounded values (`EncodeError` when set). The
  `.pyi` stub is checked with a usage script under `mypy --strict` and with
  `python -m mypy.stubtest golden` (skipped if mypy is not installed).
- **Dart**: package `golden/dart/`:
  ```
  cd golden/dart
  dart pub get
  dart run tool/embed_manifest.dart --check   # test/manifest.g.dart == vectors/manifest.txt
  dart analyze
  dart test -p vm,chrome                      # VM and dart2js; CHROME_EXECUTABLE if needed
  dart test -p chrome --compiler dart2wasm
  ```
  The tests import the generated code directly from `../gen/dart/golden.dart` (relative
  import, works on all three platforms). The browser has no file I/O, so the manifest
  reaches the tests as the string constant `goldenManifest` in `test/manifest.g.dart`,
  written by `tool/embed_manifest.dart`; `test/manifest_up_to_date_test.dart` (VM only)
  and `embed_manifest.dart --check` (run_all.sh) fail if it differs from
  `vectors/manifest.txt`. Error kinds map by name: the manifest name is the
  `BitisDecodeErrorKind` name with an upper case first letter (`unexpectedEnd` ->
  `UnexpectedEnd`). `invalid` records accept only a `BitisDecodeException` of that kind
  (any other exception fails). Besides the checks of the table above and the spot checks
  of the Rust/C++ tests (Int64/BigInt limits, fixed point values and states incl. the
  default Overflow, strings, enum/oneof variants, nested fields; encoder:
  `fixedpoints_ties`, `fixedpoints_gnss`, `fixedpoints_underflow`, `ints_min`,
  `texts_values`, defaults; out-of-range values throw `BitisEncodeException`
  `valueOutOfRange`), every `valid` case is also decoded, converted with `toJson` to a
  JSON string and back with `fromJson`, and must re-encode to the same bytes.

## CRC-32 vectors

`vectors/crc32.txt` holds test vectors of the CRC-32 helper (CRC-32/ISO-HDLC, see "CRC-32 helper" in the top level
README; not part of the wire format). It is GENERATED by `vectors/crc32_gen.py` with Python's `zlib.crc32`, an
implementation independent of the bitis runtimes:

```
hex   <name> <input_hex> <crc32>     input lower-case hex, '-' = empty input
ascii <name> <input>     <crc32>     input = the ASCII bytes of the text (no spaces)
```

`<crc32>` has 8 lower-case hex digits. Cases: the check value `123456789` (`cbf43926`), empty input (`00000000`),
single bytes `00`/`ff`/`01`/`80`, 4 and 32 bytes of `00` and of `ff`, short ASCII strings, the "quick brown fox"
sentence, the bytes `00..ff`, and `lcg_1000`: 1000 pseudo-random bytes from `x = 0x12345678`, then 1000 times
`x = (x * 1664525 + 1013904223) mod 2^32`, emit `x >> 24` (the Rust test checks the bytes against this rule).

Every runtime checks for each vector: one-shot `crc32`, incremental with two pieces split at the start, the middle,
the end and every position of inputs up to 64 bytes, three pieces with empty updates in between, byte by byte, and
`reset`:

| Runtime | Test | Run by run_all.sh |
|---|---|---|
| Rust | `tests/crc32.rs` (`cargo test --test crc32`) | rust step |
| C++ | `cpp_lib/tests/test_crc32.cpp`, compiled into `bitis_golden` twice (nibble table and `BITIS_CRC32_TABLE256`); path compiled in as `BITIS_GOLDEN_CRC32`. Building `bitis_golden` also builds `bitis_crc32_check_{nibble16,table256}` (header compiled with `-Wall -Wextra -Wpedantic -Werror -fno-exceptions -fno-rtti`, constexpr check value) | c++ steps (also ASan/UBSan) |
| Dart | `dart/test/crc32_test.dart` (vectors embedded as `dart/test/crc32_vectors.g.dart`, also written by `crc32_gen.py`; `crc32_vectors_up_to_date_test.dart` checks it on the VM); unit tests of the runtime in `dart/bitis/test/crc32_test.dart` | dart vm, chrome/dart2js, chrome/dart2wasm |
| Python | `python/test_crc32.py` (pytest, module named by `BITIS_PY_MODULE`, default `golden`; also compares with `zlib.crc32`; skipped if the module is not importable) | python step |

After changing `crc32_gen.py`: `python3 golden/vectors/crc32_gen.py` (`--check` only compares; `run_all.sh` runs
the check in the step "crc vectors up to date").

## CRC-8/16 vectors

`vectors/crc8_16.txt` holds test vectors of the CRC-8/AUTOSAR, CRC-16/IBM-3740 and transmission CRC helpers (see
"CRC helpers" in the top level README; not part of the wire format). It is GENERATED by `vectors/crc8_16_gen.py`
with plain bit-wise implementations (no tables), independent of the bitis runtimes. Fields are separated by
exactly one space:

```
hex   <name> <input_hex> <crc8> <crc16>             input lower-case hex, '-' = empty input
ascii <name> <input>     <crc8> <crc16>             input = the ASCII bytes of the text (no spaces)
frame <name> <header_hex> <payload_hex> <trailer_hex>
```

`<crc8>` has 2, `<crc16>` 4 lower-case hex digits. The `hex` / `ascii` inputs are the same as in `crc32.txt` (check
value `123456789` → `df` / `29b1`, empty input → `00` / `ffff`, ..., `lcg_1000`).

`frame` records are transmission frames of carachangprotocol `FRAMING.md` (section 2): header = bitis
`XTX_Msg_Header {bool is_encrypted; uint_2 size_low; uint_9d3 size_high}` (encoded by the script itself following
docs/WIRE_FORMAT.md), payload `p[i] = (i*37 + 1) & 0xff` (`-` = empty), trailer = CRC-8 for `n = header + payload
<= 14` bytes, else CRC-16 **little-endian** (low byte first). Names are `plain_<size>` / `enc_<size>`. The first 10
frames are the test vectors of FRAMING.md section 5; the script asserts that its headers and trailers equal the
values of that table (copied into `FRAMING_TABLE`). Additional frames: `plain_0` (header only, n = 1), `plain_14` /
`enc_14` (n = 15, the first CRC-16 frame with a 1-byte header), `plain_15` (n = 16, L = 18), `enc_31` (n = 32) and
`plain_2047` (largest size).

Every runtime checks for each `hex` / `ascii` vector both CRCs one-shot, incremental with two pieces split at the
start, the middle, the end and every position of inputs up to 64 bytes, three pieces with empty updates in between
(not Python), byte by byte, and `reset`; and, as a property of the CRC-16 function only, that the CRC-16 over the
input followed by its CRC **big-endian** is 0 (the transmission rule does not use this residue: its trailer is
little-endian). For each `frame`: the trailer length (`transmission_crc_len`), the trailer value
(`transmission_crc`, the CRC-8 / CRC-16 directly), append, verify, strip, and that every single-bit error of the
frame with trailer is rejected. Unit tests additionally cover n = 14 / 15, L = 15 / 16 / 17 (L = 16 is rejected
even if a CRC-8 or CRC-16 over its bytes would match), empty input and n = 0.

| Runtime | Test | Run by run_all.sh |
|---|---|---|
| Rust | `tests/crc8_16.rs` (`cargo test --test crc8_16`), unit tests in `src/lib_impl/crc8_16.rs` | rust step (unit tests: `cargo test`) |
| C++ | `cpp_lib/tests/test_crc8_16.cpp` in `bitis_golden` (path compiled in as `BITIS_GOLDEN_CRC8_16`; also checks the documented ESP32 ROM call against a model of `esp_rom_crc16_be`). Building `bitis_golden` also builds `bitis_crc8_16_check` (header compiled with `-Wall -Wextra -Wpedantic -Werror -fno-exceptions -fno-rtti`, constexpr check values and FRAMING.md frames) | c++ steps (also ASan/UBSan) |
| Dart | `dart/test/crc8_16_test.dart` (vectors embedded as `dart/test/crc8_16_vectors.g.dart`, also written by `crc8_16_gen.py`; `crc8_16_vectors_up_to_date_test.dart` checks it on the VM); unit tests of the runtime in `dart/bitis/test/crc8_16_test.dart` | dart vm, chrome/dart2js, chrome/dart2wasm |
| Python | `python/test_crc8_16.py` (pytest, module named by `BITIS_PY_MODULE`, default `golden`) | python step |

After changing `crc8_16_gen.py`: `python3 golden/vectors/crc8_16_gen.py` (`--check` only compares).

## Regeneration

After changing the schema, the compiler templates, or the runtime encoding:

```
cargo build
target/debug/bitis compile -l rust -i golden/schema/golden.bitis -o golden/gen/rust/golden.rs
target/debug/bitis compile -l cpp  -i golden/schema/golden.bitis -o golden/gen/cpp/golden.h --prevent-write-bitis-header-lib
target/debug/bitis compile -l dart -i golden/schema/golden.bitis -o golden/gen/dart/golden.dart
cargo run --manifest-path golden/gen_rust/Cargo.toml      # rewrites vectors/manifest.txt
(cd golden/dart && dart run tool/embed_manifest.dart)    # rewrites dart/test/manifest.g.dart
```

Review the diff of `vectors/manifest.txt`: changed bytes of existing cases mean the wire
format changed, which must not happen without a spec change. New cases are added in
`gen_rust/src/main.rs` (`valid`, `noncanon`, `invalid*`, `truncations`).

## Older cross-language framework (test_cases/)

`test_cases/t_*` exchange `.dat` files between the languages. Each `build.sh` now calls
the shared runner `test_cases/run_case.sh` (current compiler CLI, relative symlinks,
configurable via `BITIS`, `CARGO_FLAGS`, `CPP_BUILD_DIR`). All 8 cases pass for Rust and
C++, including decoding the committed `*.py.dat` files; the Python side is skipped unless
`test_cases/impl/python_impl/.venv` and maturin are available. Running a case rewrites the
generated `impl/*/messages.*` and the `.dat` files. The golden vectors supersede this
framework for wire format conformance (e.g. the GNSS fp_34/fp_35 types that are commented
out in t_simple_msg are covered here).
